# 文字算法 0.4.0

保留文字极性与局部背景联合约束、逐笔画前景/背景配对；新增图片环境约束、字缝／容器边缘验证、笔画宽度筛选及有限方向重测，取消整行估色低对比度回退。输入仍为原始分辨率 PNG，CPU 计算，不使用 OCR、识别模型、日间参考图或控件树。

算法及论文来源见[总体方案](android-dark-mode-screenshot-detection-plan.md)第 3.4、10、25 节。相反梯度边缘配对借鉴 SWT（Epshtein 等，CVPR 2010），未实现完整 SWT；双侧背景采样、极性门控和支持阈值属于项目工程规则。候选组件可能是偏旁或粘连字符，不能等同于单字。

## 检测范围

`text.detection_mode` 有两种模式：

| 模式 | 条件 |
| --- | --- |
| `theme_mismatch`（默认） | 暗笔画必须位于深色局部背景，亮笔画必须位于浅色局部背景，且局部对比度不足 |
| `all_low_contrast` | 保留正确明暗极性的全部低对比度组合，不限制背景深浅 |

深浅判断使用 gamma-encoded weighted sRGB 的归一化亮度：深色默认 `Y <= 0.30`，浅色默认 `Y >= 0.75`；中间背景范围不进入默认专项。计算对比度时仍单独使用线性 sRGB 的 WCAG 公式。

门控依据是每个笔画配对的局部背景，不依赖整页亮度、背景异常结果或文字固定位置。默认模式下，白卡灰字不会被判为专项文字异常，但白卡仍可由背景链路发现。开启全量模式后，RGB(181,181,181) 配 RGB(245,245,245) 仍应测得约 1.88:1；此变化是检测范围的选择，没有提高或篡改其实际对比度。

## 候选验证与来源

`skinscan/textshape.py` 在连通组件分组前增加以下验证；这些组合及门限属于工程规则，不是字形识别模型。

| 处理 | 实际算法 | 来源与改编关系 |
| --- | --- | --- |
| 候选宽度一致性 | `DIST_L2, maskSize=3` 距离变换＋3×3 局部极大值近似中轴；宽度变异系数 | 距离变换基础见总体方案 [P4]；宽度一致性借鉴 SWT [P3]，未实现完整 SWT 或骨架细化 |
| 字缝／容器边缘 | 核心代表色、周围同色比例、同色 CCL、与 ROI 多侧连通、相反极性响应包围 | CCL 基础见 [P2]／[P5]；具体组合为工程规则，不是论文提供的字符分类器 |
| 图片内测量支持 | 图片内部占用、有效配对数、不同中心位置数、位置跨度与宽度一致性 | 项目工程规则；图片范围生成的 SLICO 来源见图片说明 |
| 方向重测 | 原法线失败后尝试 ±12°，沿整数像素采样，选择有效配对较多的一次 | 借鉴 SWT 相反边缘思想；角度与重试策略为工程改编 |

对同色判断，先从形态学响应较强的核心取 RGB 中位数；同色容差最多约 3 RGB 灰阶，并根据当前响应强度收紧，避免把只差 2～3 灰阶的真实弱文字与背景合并。周围同色比例至少 60%，并且核心所在同色连通块接触 ROI 至少三侧，或附近有足够相反极性响应时，才排除字缝／容器结构。不能仅凭与外界连通就删掉开口字形。

近似中轴的宽度变异系数超过 0.85 时排除不规则组件。距离变换局部极值不等于精确骨架，尖角和分叉会影响宽度；装饰字体和复杂符号仍可能误判。固定的外围扩张比例、相反响应占比等常数以源码为准，不能声称所有细节均可配置。

## 逐笔画测量

1. 对多尺度 Black-hat/Top-hat 和弱边缘生成的候选执行上述结构验证，再按原图坐标测量。
2. 在组件边界上均匀选择有限数量的位置；读取局部 Sobel 梯度，暗笔画沿梯度反方向、亮笔画沿梯度方向搜索内部。
3. 沿法线搜索首次离开当前组件的位置作为宽度估计。在附近一像素范围寻找梯度方向相反的边缘；检查宽度、梯度强度和忽略掩码，拒绝找不到另一侧或越过无效区域的射线。
4. 在该宽度的 35%、50%、65% 位置采样核心（可配置），检查亮度和 RGB 变化。取符合极性的稳定核心分位数，不从抗锯齿灰度推测不可见的原字体颜色。
5. 在两侧外扩与笔画宽度相关的距离，各取连续背景像素。要求不属于任何候选笔画、没有明显边缘、没有忽略像素；两侧亮度/颜色差和内部变化均须低于门限。两侧背景不同时拒绝此射线，不将按钮边界两侧混成一个背景。
6. 使用该核心与相邻背景计算一个对比度，保留其位置、边缘位置和采样质量。射线计算在每个组件内向量化，逐张释放中间图。

所有核心点、射线和背景点直接索引原始像素；没有对截图或采样剖面做缩放插值。单次采样默认最多检查 80 个边界位置。配对不足且存在行结构或几何配对证据时，最多重测两个方向（默认 ±12°）；每次独立检查核心、背景和极性，保留有效配对最多的一次，不合并重复射线。最多三次采样，CPU 成本相应增加。

## 局部支持与异常定位

先对每个组件的有效配对应用极性及背景门控，再计算低对比度配对占合格配对的比例。普通 UI 默认需要至少 3 个低对比度配对、比例至少 40%。这样一个不稳定点不会直接触发整段文字异常。

只把满足条件的组件重新组合成异常文本段。健康的深色字不会通过整行前景分位数掩盖邻近浅灰字，也不会无条件把异常框扩展到整行。单字和短文本仍保留，默认需要复核。

汇总对比度使用低对比度配对中的代表性实际样本，同时保存 P10/P50/P90 和有限数量的配对证据。前景和背景来自同一个配对；不会从不同位置拼接两种代表色。它表示受影响局部的测量，不是整个文本行的平均值。对比度刚好跨越不同严重程度阈值时，摘要等级依赖代表性样本，详情中的分位数可用于评估分布。

## 图片环境约束

图片掩码不会写入文字的 `frame.valid`。候选像素至少一半落在可信图片内部时，采用更强证据要求：有效配对和低对比度配对默认均至少 6 个；低对比度中心至少 6 个不同位置；有效中心跨度至少为组件某个方向尺寸的 30%，配对宽度变异系数不大于 0.55。内部候选仍逐笔画取原像素，稳定底色按钮、标签、单字与数字可以检出。

边界带和不确定图片使用普通文字规则；不会只凭外接框就删除其中所有文字，也没有把图片上的文字强制全都降为复核。外观像文字的图案仍可能通过，无法从截图保证识别语义。

## 无可靠测量时的处理与边界

0.4.0 删除 `_estimate_line` 和 `line_fallback` 告警路径。配对失败不能凭整行代表色认定低对比度，也不再输出估算颜色或对比度。

无配对告警、尚有采样不足的 UI 组件时，先做局部明暗极性／背景范围预筛，再检查其能否组成高度较一致、横向且至少包含 `min_line_components` 个组件的结构；符合时输出 `UNREADABLE_TEXT_CANDIDATE`，`measurementMethod: unmeasured_text_structure`、`requiresReview: true`，不附 `contrastRatio`。预筛颜色只决定是否保留未知项，不作为实际对比度测量。图片内部的未测候选与孤立弱碎片只计入诊断，不生成这种行结构未知项。

已测得可靠配对的单字、数字不受此未知项的多组件条件限制，仍照常保留。一个未测成功的孤立单字也可能只留在诊断中；不能把没有告警解释为所有文字已测量。

复杂纹理、没有稳定核心的极细字体、笔画交点和图像边界可能导致更多射线被拒绝。局部背景在小范围变化平缓时仍可能测量；两侧或核心不稳定时会丢弃配对。方向重测不会放宽颜色或背景门限；当前没有跨尺度稳定性投票或新增背景噪声估计方法。

`strokePairs` 中只保存有限数量的低对比度样本用于检查，全部有效配对仍参与统计。`strokePairCount` 是受影响组件的有效配对总数，`eligiblePairCount` 是符合检测模式的数量；`lowContrastPairCount` 是对比度不足的数量，比例分母为合格配对数。置信度仍是启发式评分，不能解释为概率。

`modules.text.candidateValidation` 记录字缝／容器拒绝、不规则宽度拒绝、接受数、方向重测、UI／图片内未测组件及图片配对不足等计数。被拒绝的碎片不会写成文字缺陷。`unmeasuredTextIssueCount` 记录强结构未知项，旧字段 `fallbackIssueCount` 保留为 0 便于兼容。调试模式保存初始与 `*_validated_mask` 原尺寸掩码。

旧版 `fallback_core_quantile`、`background_padding_ratio`、`background_exclusion_ratio`、`core_distance`、`min_core_pixels`、`max_internal_external_delta`、`background_delta_fraction` 等整行估色参数仍接受以兼容旧配置，但已不用于这条被删除的路径。

## 验证

`tests/test_strokes.py` 覆盖默认白卡灰字过滤、全量模式约 1.88:1、混色文字局部定位、整页偏亮但局部暗背景的检测、两侧背景冲突拒绝、抗锯齿核心测量、忽略边缘、页面门限覆盖及配对失败的未知分流。原有背景、短文本、异常隔离、报告和 CI 测试继续执行。

示例 `examples/config.yaml` 为 `mixed_foreground` 页面单独启用全量模式，便于在同一份报告中比较白卡灰字过滤与混色文字检测。`examples/all-low-contrast.yaml` 则对所有页面启用全量模式。

`tests/test_text_validation.py` 新增可读文字字缝、导航栏圆角、图片纹理、图片内部弱标签／数字、仅差 2～3 灰阶的真实弱字、无测量时不生成对比度、配置边界等行为验证。
