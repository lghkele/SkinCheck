# Android 暗夜模式截图自动检测设计方案

> 修订日期：2026-10-20；算法基线：SkinScan 0.4.0。
> 本版保留“文字极性＋局部背景约束”和“局部笔画配对取样”，新增常见底色候选、纹理／边界／布局证据与候选原图 ROI 的 SLICO 图片定位；可信内部用于背景过滤，也作为文字候选加强验证的上下文；新增字缝／容器结构与宽度筛选、有限方向重测，取消整行估色告警。第 3.4 节先列算法与来源，各处理章节开头再注明适用方法。论文、技术标准与项目自定义规则分开标注，未实现能力单独说明。

## 1. 文档目的

本文设计一套基于 Android 页面截图的暗夜模式自动检测系统，用于发现页面或组件未正确适配暗夜模式的问题。

方案只分析最终截图，不依赖页面固定内容、设计稿、控件树或文字内容。核心使用传统图像处理算法，不使用 OCR、神经网络或大型视觉模型，可以在普通开发电脑和 CI 机器上直接处理原始分辨率截图。

---

## 2. 背景

Android 应用完成暗夜模式适配后，需要对大量页面、弹窗和业务状态进行视觉回归。

常见问题包括：

1. 页面已经变成深色，但某个卡片、弹窗、输入框或列表项仍然是白色。
2. 背景已经变成黑色或深灰色，但文字仍然是黑色或深灰色，导致内容无法阅读。
3. 整个页面、WebView 或局部容器没有响应暗夜模式。
4. 次要文字、按钮文字、提示文字与背景的对比度不足。
5. 图片、广告、Logo、二维码等正常亮色内容被误判为暗夜模式问题。

完全依靠人工检查存在以下问题：

- 页面和业务状态数量多。
- 低频页面、异常状态和临时弹窗容易遗漏。
- 不同业务模块适配进度不一致。
- 每个版本都要进行重复检查。
- 低对比度文字不容易被快速发现。
- 测试结果依赖检查人员的主观判断。

因此，需要使用自动化截图和图像分析，将明显异常页面自动筛选出来，缩小人工复核范围。

## 3. 设计约束与结论

### 3.1 已确认的约束

- 页面内容可能动态变化。
- 不依赖固定文字、固定数据或固定控件位置。
- 不进行文字内容识别。
- 不使用 OCR。
- 不使用 DBNet、CRAFT 等神经网络文字检测模型。
- 不使用大型视觉模型。
- 不使用 GPU。
- 不生成缩略图，不降低截图分辨率。
- 直接处理原始 PNG 截图。
- 日夜截图对比不是核心能力。
- Android 设备负责运行自动化和截图，检测程序建议运行在开发电脑或 CI 机器上。

### 3.2 核心设计结论

图片定位预处理完成后，系统使用两条相互独立、并行执行的检测链路：

1. **背景异常检测链路**：发现白斑、白色卡片、浅色弹窗和整页未切换主题。
2. **文本可读性检测链路**：默认专项模式发现深色背景上的更暗笔画、浅色背景上的更亮笔画；可选全量模式检测其他低对比度组合。每次使用具体笔画附近的背景，不能用整页主题或白斑结果代替局部判断。

图片定位不改变原图亮度、不代表封面语义识别；可信内部用于背景过滤，文字仍使用完整有效像素，但图片内候选需要更强配对和空间支持。

文本检测不能依赖背景检测结果。黑字深色背景不会产生亮色异常，如果只在白斑区域检测文字，就会漏报。

### 3.3 方案评审后的补充原则

- 窄边、细边框和环形边缘不能仅按面积过滤，需要单独保留连续长度和边缘结构。
- 亮色绝对阈值和局部反差阈值是两条独立规则，不能互相替代。
- 筛选亮度 Yg 与对比度相对亮度 L 分别明确定义，各自阈值保持一致，不混用。
- 文字边缘用于定位，文字核心像素用于估算前景颜色，避免抗锯齿像素造成误判。
- 文本检测需要覆盖短文本、单字和单个数字，不能只要求一行包含多个字符。
- 检测结果必须区分“正常”“发现异常”和“无法可靠判断”。

| 处理环节 | 采用算法或规则 | 来源及关系 | 当前状态 |
| --- | --- | --- | --- |

| 灰度／筛选亮度 | 编码 sRGB 加权值；不等于线性相对亮度 | 工程筛选定义；与 [S1] 的线性公式明确区分 | 已实现 |

| 背景块连接、边界提取 | 闭运算、腐蚀等数学形态学 | 直接使用算子；理论参考 [P1]，API [D1] | 已实现 |
| 背景块和文字小块分割 | 8 邻域连通域标记 CCL | 经典基础 [P2]；OpenCV 4.14 默认 8 邻域后端见 [P5]、[D1] | 已实现；不承诺所有版本后端相同 |
| 背景几何与均匀度 | 面积、矩形度、亮度／颜色标准差 | 工程统计与筛选规则 | 已实现 |
| 窄边／残缺边框 | 原始掩码连通域、外接框跨度、边带像素占比 | 工程规则；不使用霍夫直线或轮廓拟合论文算法 | 已实现，低置信度 |
| 背景外围反差 | 外扩环形带、中位数、区域差值 | 工程局部采样规则 | 已实现 |
| 明暗笔画候选 | 多尺度 Black-hat／Top-hat，跨尺度取最大响应 | 形态学参考 [P1]；尺度融合为工程规则 | 已实现；没有跨尺度投票 |
| 弱边缘和方向 | 3×3 Sobel 一阶梯度 | 直接使用 Sobel；以技术文档 [D2] 为依据，不虚构原始期刊论文 | 已实现；不是 Canny |
| 文字小块筛选和行分组 | 高度、宽高比、填充率；水平邻接图及并查集合组 | 几何组合为工程规则；排列思想与 [P3] 相关但不是其完整分组算法 | 已实现，主要适配水平文字 |
| 笔画两侧配对 | 沿梯度法线搜索反向梯度边缘、估计宽度 | **借鉴 SWT [P3]**，不生成全图 SWT、不复现完整 SWT 检测器 | 已实现 |
| 笔画核心＋两侧背景取色 | 宽度内多点取样、分位数／中位数、两侧一致性拒绝 | 本项目工程改进；采样比例等没有论文保证 | 已实现 |
| 极性＋局部背景门控 | 暗笔画＋暗背景、亮笔画＋亮背景 | 本项目专项规则；不是 SWT 或 WCAG 规定 | 已实现 |
| 局部低对比度支持 | 每组件最少配对数、低对比度占比、异常组件重新分组 | 工程规则；不是完整字符分割或单字识别 | 已实现 |
| 字缝／容器结构排除 | 周围同色比例、同色 CCL 与 ROI 外围连通、相反极性包围响应 | CCL 基础 [P2]／[P5]；组合为工程规则 | 已实现，不是字形识别 |
| 候选宽度筛选 | 距离变换＋局部极大值近似中轴、宽度变异系数 | 距离变换参考 [P4]、[D1]；借鉴 [P3] 宽度一致性，非完整 SWT | 已实现 |
| 有限方向重测 | 法线附近 ±12°，重用原图像素和严格颜色检查 | 项目改编，不是论文推荐角度 | 已实现，最多两次重测，不合并重复样本 |
| 图片内文字证据 | 更多配对、不同中心数、跨度和宽度一致性 | 项目工程规则；图片图案仍可能通过 | 已实现，未删除文字有效像素 |
| 无配对的 UI 文字结构 | 检测范围预筛、组件高度一致性及横向排列 | 工程规则，不估算对比度 | 已实现；整行估色告警已删除 |
| 图片范围候选 | 平坦底色学习、非底色掩码、开闭运算＋CCL | 底色与范围为工程规则；算子参考 [P1]、[P2]、[P5] | 已实现，原分辨率 |
| 图片证据与重复布局 | 局部 RGB 标准差／Sobel 密度、4×4 覆盖、主色、内外边界及重复尺寸排列 | 项目工程规则；不是图片语义分类器 | 已实现，弱证据保留复核 |
| 图片内部支持掩码 | Lab 输入的 SLICO 超像素、连通性与区域占用率筛选 | 调用 OpenCV [D3]；方法参考 [P6]；占用率和保护带为工程改编 | 已实现，仅候选原图 ROI，无缩放 |
| 图片／复杂纹理降分 | RGB 标准差＋Sobel 边缘密度 | 工程启发式；不是 Haralick 共生矩阵 | 保留背景纹理评分 |
| 坐标／颜色白名单 | 掩码、RGB 容差、风险降分 | 工程规则 | 已实现 |
| 模板白名单 | 可选归一化相关模板匹配 | 可用 OpenCV `matchTemplate` [D1]；不归为已实现论文方法 | 未实现，可选 |
| 同类异常合并、父子嵌套 | IoU、包含率、类型／测量相容性 | 工程后处理；不是完整 NMS／Soft-NMS | 已实现 |
| 风险、置信度、CI 分流 | 对比度分档＋启发式评分＋规则状态机 | 对比度公式见 [S1]；风险权重与分流为工程规则 | 已实现，非概率模型 |
| HTML／JSON／历史与复核 | 原图坐标记录、批处理和工件保存 | 工程输出，无论文算法 | 已实现 |

本方案没有用于“理解某个字长什么样”的字典或识别模型。形态学、几何排列与相反梯度配对只能支持“像文字／笔画”的假设，不能证明候选一定是文字，也不能稳定给出一个候选对应哪个字。

## 4. 建设目标

### 4.1 功能目标

系统需要自动发现：

- 大面积白色或浅色背景。
- 夜间页面中的局部异常亮色模块。
- 页面主体整体过亮。
- 深色背景上的黑色或深灰色文字。
- 浅色背景上的白色或浅灰色文字。
- 启用全量可读性模式时，检测其他文字与背景对比度不足的区域；默认专项模式不覆盖全部组合。
- 新版本引入的暗夜模式视觉回归。

### 4.2 输出目标

每次检测输出：

- 原始截图。
- 带异常框和标签的结果图。
- 异常区域坐标。
- 异常类型。
- 区域亮度、背景亮度和亮度差。
- 文本与背景对比度。
- 风险等级。
- 检测置信度。
- 触发的规则及判断依据。
- JSON 结构化结果。
- 可选 HTML 汇总报告。

### 4.3 工程目标

- 只依赖 CPU。
- 支持普通电脑和 CI 机器。
- 支持原始分辨率截图。
- 支持批量处理。
- 支持页面、坐标和颜色白名单；模板白名单保留为可选扩展。
- 所有阈值可配置。
- 同一张截图能够同时报告多个异常。
- 单个检测模块失败时不影响其他模块运行。

### 4.4 非目标

当前方案不负责：

- 判断页面是否完全符合设计稿。
- 识别截图中的具体文字内容。
- 理解业务语义。
- 精确识别每一种 Android 控件。
- 判断图片内容本身是否适合暗夜模式。
- 发现截图中已经完全不存在视觉信息的文字。
- 完全替代人工视觉验收。

系统定位是“视觉问题筛选器”，不是完整的设计验收系统。

## 5. 问题分类与检测方案

算法与来源已在第 3.4 节预先标注；本节给出问题到处理链路的对应关系。

| 问题类型 | 示例 | 主要算法与适用模式 |
| --- | --- | --- |
| 大面积白色背景 | 白色卡片、白色弹窗 | 阈值＋形态学 [P1]＋CCL [P2]／[P5]＋工程均匀度规则 |
| 局部浅色模块 | 浅灰卡片、浅色输入框 | 多档阈值＋外围中位数反差，工程规则 |
| 整页未切换主题 | WebView 仍为白色 | 全页统计＋最大连续低纹理亮区，工程规则 |
| 暗字深底 | 黑字显示在深灰底 | Black-hat [P1]＋Sobel [D2]＋SWT 思想配对 [P3]＋局部门控＋WCAG [S1]；两种模式均覆盖 |
| 亮字浅底 | 白字显示在浅灰底 | Top-hat [P1]＋同上配对测量；两种模式均覆盖 |
| 灰字白底等其他低对比度 | 次要文字或禁用态 | 只有 `all_low_contrast` 覆盖；不能从截图推断设计意图 |
| 图片造成误报 | 封面、头像、广告 | 底色候选＋纹理／边界／布局＋SLICO [P6]；可信内部过滤背景，边界和不确定区域复核 |
| 正常品牌色 | 强调按钮、Logo | 页面／颜色白名单，工程规则；不能因此跳过其上文字测量 |

## 6. 总体架构

> 算法：图片定位预处理＋两条独立链路＋共享只读基础图；工程架构。各算子来源见第 3.4 节，不把整个流水线归因于一篇论文。

```text
原始 PNG＋暗夜模式元数据
        ↓
无损解码、忽略掩码、编码亮度 Yg、灰度、Sobel 梯度
        ↓
底色／纹理／边界／布局提出图片范围→候选原图 ROI 的 SLICO
（背景排除可信内部；文字保留有效区，内部候选加强证据要求）
        ↓
┌─────────────────────────────┬──────────────────────────────────┐
│ 背景异常链路                 │ 文本可读性链路                    │
│ 页面整体亮度统计             │ Black-hat / Top-hat 多尺度响应     │
│ 绝对／相对／局部阈值         │ 残差噪声门限＋Sobel 弱边缘         │
│ 闭运算块状分支＋原掩码窄边   │ CCL 候选小块＋水平行分组           │
│ CCL＋几何／均匀度            │ 每组件：相反梯度笔画边缘配对       │
│ 外围环带反差＋纹理降分       │ 核心与两侧背景的稳定性检查         │
│                             │ 极性＋局部背景门控                 │
│                             │ 每对 WCAG 对比度→组件支持判定     │
│                             │ 仅异常组件重新组合为局部文本段     │
│                             │ 无测量时仅保留强 UI 结构未知项     │
└─────────────────────────────┴──────────────────────────────────┘
        ↓
同类重复证据合并、白名单、背景／文字父子关系
        ↓
严重程度＋启发式置信度＋人工复核状态
        ↓
标注 PNG、JSON、HTML、可选严格 CI 判定
```

图片定位故障时记录错误，背景回退为不排除图片、文字继续运行。剩余 UI 太少时背景分析标记不完整。背景链路不能为文字链路提供“是否执行”的前置条件。文本行用于组织候选，不用于把一行全部颜色压成一组前景／背景。纹理和采样质量在相应链路内部评估，不在合并前统一删除所有高纹理区域。

## 7. 输入设计

> 算法：PNG 无损解码、元数据校验及掩码管理，工程处理；不涉及文字识别论文。

### 7.1 截图要求

- 使用 PNG 等无损格式。
- 保留设备原始截图分辨率。
- 不使用 JPEG 压缩。
- 不进行二次缩放。
- 截图前尽量等待页面主要动画结束。
- 固定设备字体大小和显示缩放。
- 状态栏和导航栏可以保留，也可以通过配置忽略。

弱对比度文字可能只有十几个灰度级差异，有损压缩或缩放会直接破坏这些信息。

### 7.2 页面元数据

建议为每张截图记录：

```json
{
  "pageId": "music_home",
  "caseId": "music_home_default",
  "theme": "dark",
  "device": "device_name",
  "androidVersion": "version",
  "width": 1080,
  "height": 2412,
  "capturedAt": "timestamp",
  "imagePath": "screenshot.png"
}
```

页面内容允许变化，`pageId` 主要用于应用页面级配置和白名单，不用于固定截图匹配。

## 8. 截图预处理

### 8.1 图像数据与两个亮度定义

> 算法：编码 sRGB 加权筛选值（工程定义）＋线性 sRGB 相对亮度（WCAG 标准 [S1]）。两套阈值不得互换。

从原始图片生成原始 RGB、8 位灰度、筛选亮度 `Yg`、有效像素掩码和 Sobel 梯度，尺寸均与输入相同。

**筛选亮度 `Yg`**：用于背景阈值、局部深浅门控、噪声与梯度等工程筛选。令 `r,g,b` 为原始 8 位通道除以 255 后的编码值：

```text
Yg = 0.2126r + 0.7152g + 0.0722b
gray = round(255 × Yg)
```

这里没有执行线性化，因此 `Yg` 不是物理亮度，也不是 WCAG 相对亮度。现有配置中的 `0.30`、`0.75`、`0.80` 等深浅阈值均按这个定义校准；实现输出中的相关 `Luminance` 字段按此解释。

**相对亮度 `L`**：只用于每对前景／背景的 WCAG 对比度。对每个编码通道 `c`：

```text
c_linear = c / 12.92                     当 c <= 0.04045
c_linear = ((c + 0.055) / 1.055)^2.4      其他情况
L = 0.2126r_linear + 0.7152g_linear + 0.0722b_linear
```

不能把 `Yg` 直接代入 WCAG 公式；也不能把 `Yg <= 0.30` 改成 `L <= 0.30` 而保留同一门限。当前实现没有启用 Lab 分支；后续若引入，必须独立命名和校准阈值。

### 8.2 降噪与局部噪声估计

> 算法：3×3 中值滤波、绝对残差、局部 box filter；基础算子见 [D1]，残差门限组合为工程规则，无对应专门论文。

文字候选仍从原始灰度图生成。中值图仅辅助估计局部变化，不替代原始笔画颜色：

```text
residual = abs(gray - medianBlur(gray, 3))
noise = boxFilter(residual, local_window)
T = clip(min_response + noise_multiplier × noise,
         min_response, max_response_noise)
```

该估计会把部分真实细笔画当作残差，不是严格的传感器噪声模型。需要通过弱字、细字与复杂纹理样本校准；当前没有新增跨尺度稳定性投票或更复杂的噪声估计。

### 8.3 忽略区域

> 算法：原图坐标布尔掩码，工程处理；任何采样不得使用忽略像素。

预处理阶段应用固定忽略区域：

- 状态栏。
- 系统导航栏。
- 测试框架叠加层。
- 已知不会参与业务页面检测的区域。

## 9. 背景异常检测设计

### 9.1 页面整体亮度检测

> 算法：原图／剩余 UI 两套亮度统计＋最大低纹理连通亮区，工程规则；CCL 基础见 [P2]／[P5]。

用于发现整个页面、WebView 或大容器没有切换到暗夜模式。

统计指标：

- 页面亮度中位数。
- 高亮像素比例。
- 暗色像素比例。
- 最大连续亮色区域占比。
- 大面积低纹理亮色区域占比。

可信图片内部排除后，整页未适配规则使用剩余 UI 的统计及面积分母；原图统计另存，不覆盖。剩余 UI 不足默认 8% 时标记分析不完整，不判通过。

初始参考规则（以下比例使用剩余 UI）：

```text
高亮像素比例 > 40%
且暗色像素比例 < 25%
且最大连续低纹理亮色区域 > 剩余 UI 面积的 30%
→ 疑似页面主体未进入暗夜模式
```

阈值必须通过应用真实截图校准，不能直接作为所有产品的统一标准。

### 9.2 亮色像素掩码

> 算法：绝对阈值＋页面中位数偏移＋多档局部阈值，工程规则；不是 Otsu 或局部自适应二值化论文的复现。

同时使用绝对阈值和页面自适应阈值：

```text
绝对高亮：Yg > 0.80
相对高亮：Yg > 页面亮度中位数 + 0.30
```

绝对、相对分支分别生成候选；另以 `Yg > 0.25/0.40/0.55/0.70` 的多档阈值寻找局部区域，再检查外围反差。当前局部分支属于多阈值枚举，不是逐像素局部均值阈值算法。相对阈值适配不同暗色主题，绝对阈值稳定发现接近白色的区域。

### 9.3 形态学处理

> 算法：数学形态学闭运算 [P1]；原始掩码独立保留。背景分支未执行开运算，图片候选分支另见第 11 节。

块状区域分支执行闭运算，连接被文字、图标或细线切开的同一块背景，然后执行小区域筛选。

窄边分支直接分析未经闭运算和开运算的原始阈值掩码，不套用块状最小面积。当前不执行开运算，以免删除 1～2 像素异常边缘；若以后增加，只能放在独立的块状分支。

形态学核大小应按截图尺寸配置，不应写死为单一像素值。

### 9.4 连通区域特征

> 算法：8 邻域 CCL [P2]／[P5]＋面积、外接框、标准差等工程统计；不使用完整轮廓拟合。

对每个候选区域计算：

- 面积和页面面积占比。
- 区域平均亮度。
- 高亮像素占比。
- 亮度标准差。
- RGB 颜色标准差（当前不启用 Lab 分支）。
- 外接矩形面积。
- 矩形度。
- 长宽比。
- 边界规则度（扩展特征，当前未独立计算）。
- 区域外围亮度。
- 区域与外围亮度差。
- 区域纹理和边缘密度。

矩形度可以计算为：

```text
矩形度 = 连通区域面积 / 外接矩形面积
```

### 9.5 背景异常初始规则

> 算法：布尔条件组合，工程规则。所有阈值均非论文给出的通用标准。

可以使用以下条件作为第一版块状区域参考：

```text
区域面积占屏幕比例 > 0.2%
且区域平均亮度 > 0.75
且高亮像素占比 > 70%
且区域与外围亮度差 > 0.25
且矩形度 > 0.65
→ 亮色背景候选
```

如果区域面积超过页面的 `5%`，并且高亮像素占比超过 `90%`，可以直接提高到严重风险。

### 9.6 窄边和环形区域

> 算法：原始掩码 CCL＋外接框跨度＋边带像素占比，工程规则；不依赖霍夫变换或闭环轮廓追踪。

当浅色外层被深色内层覆盖时，浅色区域可能只剩一圈很窄的边缘。此时实际浅色像素面积很小，但边缘仍然可能代表未适配的外层背景。

窄边候选不使用块状最小面积规则，当前检查：

- 连通区域外接框的最大边长是否达到要求。
- 是否足够细，或矩形填充率低且像素主要分布在外接框边带。
- 区域与外围是否有足够亮度差。

当前 `continuousLength` 是外接框最大跨度的近似量，不是真实弧长，也没有独立验证直线方向一致性和闭环拓扑。完整／部分环形只能由上述几何规则近似筛选，不能写成精确边框识别。

即使只有上边、左边和右边，也可以输出“疑似异常浅色边缘”，不要求必须形成完整闭合矩形。正常边框与异常外层背景在截图中可能无法完全区分，因此这类结果默认使用较低置信度，交由人工确认。

### 9.7 局部环境反差

> 算法：多档阈值生成候选＋外围环形带中位数差，工程规则，与绝对高亮分支并行。

有些未适配区域不是纯白，而是浅灰色。此时固定高亮阈值可能漏报，需要比较区域和外围环境。

局部反差规则与绝对高亮规则并行执行。一个区域不满足绝对高亮阈值时，仍然可以因为相对于附近背景明显变亮而成为候选区域。

在候选区域外扩一定范围形成环形采样带：

```text
局部亮度差 = 区域平均亮度 - 外围亮度中位数
```

使用中位数而不是平均值，可以降低文字、图标和边框对背景估算的影响。

### 9.8 亮色背景与图片的区别

> 算法：RGB 标准差、亮度标准差和 Sobel 边缘密度 [D2]；工程启发式降分，不能识别图片语义。

未适配背景通常具有：

- 面积较大。
- 颜色单一。
- 亮度均匀。
- 低纹理。
- 边界接近矩形或圆角矩形。

图片通常具有：

- 多种颜色。
- 较高颜色方差。
- 较高纹理复杂度。
- 多方向边缘。
- 内部亮度变化明显。

0.3.0 先定位可信图片范围，再以 SLICO 支持掩码排除其内部背景候选；不能只凭高纹理就删除区域。边界带、不确定图片及附近 UI 保留，原有纹理降分也继续使用。流程见第 11 节。

## 10. 文本可读性检测设计

### 10.1 检测范围与主流程

> 算法：传统形态学＋梯度＋连通域＋工程几何规则；局部边缘配对借鉴 SWT [P3]；颜色对比度使用 [S1]。

本模块不识别文字内容，也不完整分割“每个字”。候选单元是相连的像素组件：一个中文字符可能拆成偏旁或多段笔画，两个字符也可能粘在同一组件。

主流程为“候选小块→水平分组→逐组件边缘配对→局部取色→范围门控→逐配对对比度→组件支持判定→异常组件重新组合”。行分组只提供空间组织与排列证据，不能用整行最暗像素代表整行前景。

`text.detection_mode` 明确区分两种范围：

| 模式 | 判定范围 | 示例 |
| --- | --- | --- |
| `theme_mismatch`（默认） | 暗笔画＋深色局部背景，或亮笔画＋浅色局部背景，并且低对比度 | 黑字深底、白字浅底 |
| `all_low_contrast` | 极性正确的全部低对比度组合 | 还包括白底灰字、灰底弱字等 |

默认模式下，白卡灰字可能不产生文字告警，但白卡仍由背景链路独立分析。这是缩小检测范围，不是认定其可读性合格；背景中间深浅区间也可能被专项模式排除。

### 10.2 多尺度双极性候选

> 算法：Black-hat／Top-hat 数学形态学 [P1]；跨尺度最大响应是工程融合，不是 SWT 原论文的全图变换。

在原始灰度图 `I` 上使用椭圆结构元素 `K`：

```text
暗笔画响应 B = close(I, K) - I
亮笔画响应 W = I - open(I, K)
各极性响应 R = 多个 K 尺寸下响应的逐像素最大值
```

结构元素尺寸按截图宽度乘以配置比例计算，默认对应小、常规、大三个尺度。多尺度指改变算子核，截图本身不缩放。当前没有检查一个候选是否在多个尺度都稳定存在。

形态学响应只是“局部细小明暗结构”的证据：图标、边框、字符之间的空隙也会响应，不能在这一步认定文字。

### 10.3 弱边缘与噪声门限

> 算法：3×3 Sobel [D2]＋第 8.2 节残差噪声门限，组合为工程规则；不使用 Canny 或 Sauvola。

分别计算水平与垂直梯度，得到大小 `G` 和方向。每种极性的候选条件为：

```text
candidate = (R >= T) OR
            ((G > T/255) AND (R >= T × weak_response_fraction))
candidate = candidate AND valid_mask
```

默认 `weak_response_fraction = 0.50`。Sobel 并非完全独立地把所有边缘加入文字候选，仍要求对应形态学响应，减少按钮边缘和纹理混入。门限噪声单位来自 8 位灰度；梯度在编码亮度上计算，二者转换关系属于工程门限设计。

### 10.4 候选形状与水平文本行

> 算法：8 邻域 CCL [P2]／[P5]＋距离变换 [P4]＋同色／相反极性结构＋几何过滤＋水平邻接关系合组，组合为工程规则；不使用字形模板，也不识别笔顺。

1. 把候选像素按相邻关系连接成小块。
2. 按高度范围、最小面积、宽高比和填充率筛选。填充率是候选像素面积除以外接矩形面积，过实的大块和过散的噪点被排除。
3. 新增同色与结构验证：从强响应核心估计代表色；周围同色像素至少 60%，且核心同色连通块接触局部 ROI 至少三侧，或有相反极性响应包围时，排除背景字缝／容器结构。RGB 容差随当前响应收紧，保护差值仅 2～3 灰阶的真实弱字。
4. 距离变换 [P4] 的局部极大值近似中轴，估计宽度变异系数；超过默认 0.85 则排除不规则组件。不是精确骨架，也不是完整 SWT。
5. 高度相近、垂直重叠足够、水平间距合理的组件归为一组。实现以邻接关系和并查集合组，允许通过相邻组件传递连接。
6. 多组件且整体偏横向的组获得额外行结构支持；短文本和孤立候选继续测量，但降低置信度并要求复核。

“文字形状”在此仅表示像文字的局部几何结构。候选阶段采用近似中轴宽度筛选，后续还检查实际配对宽度；均不等于完整笔画宽度变换。水平合组对倾斜、竖排和装饰字体不可靠，也可能串联不应属于同一行的候选。

### 10.5 相反梯度边缘配对与宽度

> 算法：借鉴 Epshtein、Ofek、Wexler 的 SWT [P3] 中“沿梯度搜索相反边缘”的思想；使用 Sobel，组件内部射线采样为项目改编，**不是完整 SWT 实现**。

对每个候选组件：

1. 用组件减去其腐蚀结果得到边界，按边界像素索引近似均匀抽样，默认最多 80 个位置；并非按真实轮廓弧长等距抽样。
2. 读取 Sobel 梯度。暗笔画沿梯度反方向进入内部，亮笔画沿梯度方向进入内部。
3. 沿射线搜索首次离开当前组件的位置，作为局部宽度估计；检查附近 ±1 像素是否存在足够强且方向相反的梯度。
4. 检查最小宽度、相对于组件高度的最大宽度，以及忽略掩码。找不到另一侧、越界或进入无效区域时拒绝该射线。

```text
暗笔画截面：背景 → 变暗边缘 → 笔画内部 → 变亮边缘 → 背景
                          ← 局部宽度 →
```

配对不足且存在行结构或初步几何证据时，额外尝试法线两侧默认 ±12° 的方向，每次完整执行相同颜色／背景检查，只保留有效配对最多的一次，不合并重复射线。最多三次采样，截图和剖面均不缩放。

这是对若干局部笔画截面的采样，不追踪完整横竖撇捺，也不保证遍历组件每一段笔画。宽度受二值候选边界影响，不是精确的字体轮廓宽度。

标准 SWT 还包含全图笔画宽度赋值、宽度一致组件与字符链等步骤。本实现没有这些完整步骤，也没有直接复用论文中的整套检测器或阈值，不能简称“已实现标准 SWT”。

### 10.6 核心与两侧背景成对取样

> 算法：笔画宽度内多点取样＋局部分位数／中位数＋双侧一致性拒绝，项目工程改进；[P3] 仅是几何配对思想来源，未提供本节采样阈值。

对每条几何合格的射线：

- 在内部采样区间的约 35%、50%、65% 处取核心点（可配置；实际索引按原图整数坐标计算）。
- 检查核心亮度与 RGB 变化，优先用符合极性的稳定核心分位数，避免一个极端像素决定颜色。
- 在笔画两侧留出与宽度相关的间隔，再各取连续背景像素，默认每侧 3 点。
- 背景点必须有效、不属于当前极性掩码中的任何候选组件、没有强梯度；检查两侧颜色／亮度是否接近，以及合并后的变化是否足够小。
- 任意一侧不稳定或两侧明显不同时，拒绝整对采样，不能跨按钮边界把不同背景平均成一种颜色。
- 用该局部核心的统计代表色与同一截面邻近背景的统计代表色组成一对；不把本行左端的前景与右端背景拼在一起。

所有采样直接索引原始 RGB 像素，不缩放、不插值，也不反推未渲染字体的“原始颜色”。代表色可能是邻近多个像素的中位数，不能表述为还原了设计稿色值。抗锯齿只用于定位和质量筛选；极细字没有稳定核心时，采样可能失败。

当前双侧背景排除依据是当前极性的候选标签，其他极性结构主要由梯度和稳定性检查拦截；不能保证识别所有邻近图案。稳定性检查也不能证明背景在语义上属于同一控件。

### 10.7 极性与局部背景门控

> 算法：项目自定义的专项范围门控，无对应专门论文；不是 [P3] 或 [S1] 的规定。

先确认核心相对于背景的明暗方向符合候选极性，并达到 `min_foreground_delta`。然后在默认模式应用：

```text
dark_candidate：Yg_fg <= Yg_bg - min_foreground_delta
                且 Yg_bg <= dark_background_max（默认 0.30）
light_candidate：Yg_fg >= Yg_bg + min_foreground_delta
                 且 Yg_bg >= light_background_min（默认 0.75）
```

深浅依据来自**这一对采样附近的背景**。整页大部分是浅色，也不能阻止局部深底黑字被发现。`all_low_contrast` 只取消背景深浅门控，保留极性正确性与采样质量检查。

### 10.8 每对 WCAG 对比度与组件支持

> 算法：WCAG 2.2 相对亮度对比度 [S1]＋最少配对数／占比支持的工程规则。

每对颜色单独按第 8.1 节线性化并计算：

```text
Contrast = (max(L_fg, L_bg) + 0.05) / (min(L_fg, L_bg) + 0.05)
eligible = 采样有效且符合当前检测范围的配对
low = eligible 中 Contrast < warning_contrast 的配对
```

普通 UI 组件默认需要至少 3 个低对比度配对，且 `len(low) / len(eligible) >= 0.40` 才成为异常组件。可信图片内部候选则默认至少 6 个有效配对及 6 个低对比度配对，弱配对中心至少 6 个不同位置；有效中心跨度至少覆盖组件某个方向尺寸的 30%，配对宽度变异系数不超过 0.55。占比分母是符合范围的配对数，不是所有尝试射线数；只出现一个弱点不直接触发整个组件。

最少 3 对和 40% 均为可校准工程门限，不是统计显著性检验，也不保证样本相互独立。若一个组件粘连了多个字符，判定仍作用于组件，不能保证逐字边界准确。

| 配对对比度 | 项目风险分档 | 解释 |
| ---: | --- | --- |
| `< 2:1` | 严重 | 项目内部风险等级，并非 WCAG 单独规定的严重等级 |
| `2:1～<3:1` | 高风险 | 同上 |
| `3:1～<4.5:1` | 中风险 | 需结合字号、用途与设计意图复核 |
| `>= 4.5:1` | 本规则不告警 | 不等于整页或控件已通过全部可访问性要求 |

WCAG 对普通文字与大字有不同要求，禁用控件和 Logo 等也存在例外。截图算法没有可靠的语义和字号信息，统一 4.5:1 仅作为筛选门限，不能宣称完整 WCAG 审计。

### 10.9 一行文字的局部处理与证据

> 算法：异常组件重新分组＋局部对比度分布统计，工程规则；不做整行颜色池化。

以同一行 `GOOD weak` 为例：

1. 空间上可以先属于同一候选组，但分别在各组件测量。
2. `GOOD` 的有效配对对比度足够，不进入异常组件集。
3. `weak` 的组件有足够弱对比度配对，进入异常组件集。
4. 仅对异常组件重新进行邻接分组，异常框覆盖受影响局部，而不是无条件覆盖整行。

如果原始连通域已把正常和弱字符粘成一块，定位只能达到该组件粒度；不能把它描述成保证逐字准确的算法。

结果记录有效／合格／低对比度配对数、比例、拒绝背景数量和有限数量的位置证据。摘要对比度选择低对比度配对中接近中位数的一对，并保留该对的前景与背景；P10/P50/P90 也按低对比度配对统计，不是整行所有文字的对比度分布。摘要等级据代表对计算，因此极少数更差局部可能只体现在证据中，不能把摘要值当作最差值。

### 10.10 无可靠测量时的处理

> 算法：局部检测范围预筛、组件高度一致性与水平结构规则；工程设计。0.4.0 删除整行估色低对比度回退。

可靠配对是生成 `LOW_CONTRAST_TEXT` 的前提。无法配对时，不从整行颜色池估计对比度。没有配对告警、剩余未测 UI 候选符合局部极性／背景范围、且能形成至少 `min_line_components` 个高度相近的横向组件时，保留 `UNREADABLE_TEXT_CANDIDATE`、`measurementMethod: unmeasured_text_structure` 和人工复核标记，不输出估算前景、背景或 `contrastRatio`。

可信图片内部未测碎片、不足以形成文字结构的孤立候选只记录诊断计数。图片上的稳定底色标签和已测成功的单字／数字仍可告警。一个测量失败的孤立真实单字可能只留在诊断中；未告警不能视为全部文字均完成测量。图片定位不确定和边界带使用普通规则，不能保证所有图文都可区分。

`modules.text.candidateValidation` 记录结构拒绝、接受组件、重测、未测 UI／图片组件及图片配对质量不足等数量。旧 `fallbackIssueCount` 兼容保留为 0；调试输出增加 `*_validated_mask`。已删除整行估色路径的旧参数仍接受以兼容配置，但不再影响测量。

### 10.11 置信度与能力边界

> 算法：高度一致性、配对宽度一致性、低对比度支持比例的启发式加权，工程规则；不是经过标注训练或校准的概率。

严重程度描述测得的对比度风险，置信度描述候选与测量证据强弱，两者分开。短文本或孤立组件的配对告警置信度最多 0.68，并保留人工复核；不能因字符少而一律删除。

仅靠截图无法保证区分文字与图标。极细字体、笔画交点、装饰字体、图片背景、渐变、低于门限的弱边缘可能测量失败；完全同色文字没有可恢复信息。当前不做完整字形判断、跨尺度稳定性投票、OCR、标准全图 SWT、字体颜色反演或自动设计意图识别。

## 11. 图片和动态内容过滤

### 11.1 目的与边界

> 算法：底色与几何工程候选＋纹理／边界／布局规则＋SLICO [P6]、[D3]。识别“有图片证据的区域”，不识别书名、人脸或封面语义。

图片在暗夜模式下可以保持原始亮度。这里消除的是它们引起的背景告警，不修改截图、不压暗图片。全程 CPU、原始像素；不使用 OCR、神经网络和缩略图。

### 11.2 生成与验证候选

> 算法：局部 RGB 标准差与 Sobel [D2]、量化颜色频数、开闭运算 [P1]、CCL [P2]／[P5]；组合与门限均为工程规则。

1. 在局部颜色平稳、梯度低的位置学习频繁 UI 底色，实际底色取原像素中位数。
2. 以非底色像素形成候选。同时比较排除全部常见底色、只排除较暗底色两种提案，兼顾白卡内部嵌图与封面中的白色天空。
3. 用独立 3×3 开闭运算和连通域提出范围，检查面积、宽高和占用率。比较原范围与去掉狭窄附着物后的范围，保留证据较强的一项。
4. 检查颜色／边缘细节是否覆盖多个位置、4×4 网格覆盖、主色占比和候选内外边界差异。纯色卡片、按钮和密集文字负样本不能仅凭边缘多就被过滤。
5. 去重后，尺寸相近、同行／同列及合理间距仅作为加分。没有重复同伴的独立大图仍可采用，布局不能替代内部和边界证据。

最多分析 80 个候选；达到上限记录模块 `partial`，保留不完整分析信息。候选弱、无足够平坦底色或边界不足时不自动排除。

### 11.3 超像素内部支持

> 算法：OpenCV SLICO [D3]，方法来源 [P6]；原图 ROI、标签占用率、保护带和降级规则为项目改编。

在可信候选及其小范围外围的原图 ROI 转为 Lab 后执行 SLICO，默认 4 次迭代并处理标签连通性。选择内部占用率足够的超像素，裁回有效候选范围，内缩约截图宽度 0.2% 留保护带。支持覆盖率不足时整个候选降为不确定。

当前不是整页先做 SLICO 再识别图片。分割只约束候选内部支持，不能独立证明矩形是图片，也不能保证精确轮廓。详细步骤与来源见[图片算法说明](/Users/kele/Downloads/code/SkinScan/docs/picture-algorithm.md)。

### 11.4 检测链路如何使用

> 算法：专用内部掩码、原始连通结构、剩余 UI 统计与人工复核，均为工程规则。

- 可信内部只从背景块候选、外围取样及相应纹理统计中排除，不写入 `ignored_regions`，不改变文字链路的有效像素。
- 边界带与不确定图片不自动排除；与其重合较多的背景告警降为复核。
- 窄边使用扣除图片之前的阈值连通结构，避免挖空内部制造假边框；主要落在可信内部的原始边缘候选过滤，图片外真实细边仍检测。
- 整页未适配使用剩余 UI 统计。UI 太少时标记分析不完整；不确定图片占大部分剩余亮区时整页告警降为复核。
- 文字仍逐笔画测量；可信图片内部需要更强的配对与空间支持，失败碎片只记录诊断。稳定底色标签仍可检出，未采用图片内文字统一跳过或统一复核。
- 图片模块故障记录错误并回退到未过滤背景检测，文字继续运行；执行错误不会静默通过。

### 11.5 输出、限制与后续

`statistics.pictureRegions` 保存范围、证据、采用／不确定分类及分割支持。`pictures.png` 以绿框展示采用候选、橙框展示不确定候选；框内不代表全部排除，实际掩码见调试 `pictures_interiors.png`。原图与剩余 UI 统计同时保存。

纯色海报、极简封面、边界弱或被遮挡的图片可能定位失败；底色相近可使范围收缩。悬浮 UI 与封面重叠时无法恢复语义层级，仍可能包含叠加组件。LBP、全页图分割对照和语义封面模型未实现。渐变、遮罩、动画和设计允许的弱文字仍需有效截图时机、业务配置及人工复核。

## 12. 白名单设计

### 12.1 固定区域白名单

> 算法：固定坐标掩码，工程规则。

用于忽略：

- 状态栏。
- 导航栏。
- 自动化工具悬浮层。
- 固定系统区域。

### 12.2 页面坐标白名单

> 算法：按 pageId 合并全局与页面坐标掩码，工程规则。

按 `pageId` 配置：

- 商品图片区域。
- 小说或视频封面区域。
- 地图区域。
- 二维码区域。
- 品牌 Logo 区域。

### 12.3 颜色白名单

> 算法：RGB 最大通道差容差匹配＋风险降分，工程规则；只作用于背景类异常。

对设计明确允许的品牌色、强调按钮颜色，在容差内降低背景类异常的风险与置信度，并保留复核。该规则不抑制文字异常；允许的按钮底色不代表按钮上的文字一定可读。

### 12.4 模板白名单

> 算法：可选 OpenCV matchTemplate 归一化相关匹配 [D1]；尚未实现，不作为当前能力承诺。

如果存在固定 Logo 或固定运营素材，可以使用轻量模板匹配。模板匹配属于可选能力，第一版可以不实现。

### 12.5 配置示例

## 13. 异常合并

> 算法：IoU、包含率及同类测量相容性，工程后处理；不宣称为完整 NMS 或 SWT 论文分组。

同一个 UI 问题可能被多个规则同时发现。例如，白色卡片可能同时触发：

- 高亮区域异常。
- 局部环境反差异常。
- 浅色背景上的浅色文字异常。

合并策略：

1. 计算候选框之间的 IoU 或包含关系。
2. 同类型且满足重叠／包含与测量相容规则的候选才去重；优先保留高置信度代表，其他测量写入备选证据。
3. 保留全部触发规则。
4. 以最严重的等级作为事件严重程度。
5. 保留来源与测量证据，但不能仅因同一批像素命中多个阈值就提高置信度：它们不是相互独立的证据。

背景异常框可以作为父区域，内部的文本异常作为子问题展示，避免报告中出现大量互相重叠的红框。

## 14. 风险评分设计

### 14.1 背景异常评分

> 算法：外围反差、均匀度、矩形度与纹理的启发式评分，工程规则，未经概率校准。

当前块状背景告警置信度主要综合：

```text
背景置信度 = 基础分
           + 与外围亮度差的支持
           + 区域亮度均匀度
           + 矩形度
           - 纹理复杂度惩罚
```

区域亮度、面积及亮色占比用于候选准入与严重程度；颜色白名单另行降低背景风险和置信度。阈值及部分惩罚可配置，评分系数不全部开放配置；不能把当前启发式评分当作概率模型。窄边与整页告警使用各自规则。

### 14.2 文本异常评分

> 算法：局部配对对比度分档＋组件高度／配对宽度一致性＋支持比例，工程规则；公式基础见 [S1]。

```text
配对告警置信度 = 基础分
                + 组件高度一致性
                + 局部配对宽度一致性
                + 合格配对中的低对比度支持比例
```

这是相对评分，不是文字识别概率。严重程度单独由代表性配对对比度分档；短文本保留复核。未测强结构仅输出未知项，不计算严重程度对应的对比度；整行估色告警已删除。不同阈值检测同一像素不会因重复命中自动加分。

### 14.3 建议等级

> 算法：风险分档规则；2:1、3:1、4.5:1 的项目分档不等于 WCAG 完整合规结论。

| 等级 | 示例 |
| --- | --- |
| 严重 | 大面积白色背景、文字对比度低于 2:1 |
| 高风险 | 明显浅色模块、文字对比度低于 3:1 |
| 中风险 | 小面积异常或文字对比度低于 4.5:1 |
| 可疑 | 检测置信度不足，需要人工确认 |
| 忽略 | 命中白名单或属于无意义小区域 |

## 15. 两个案例的判定示例

本节原始面积与颜色数值沿用早期方案，当前未持有这两个业务案例的原始 PNG，不能视为本版重新实测结果；0.2.0 合成样本验证另见第 21.3 节。

### 15.1 案例一：白色卡片背景

截图中的异常卡片具有以下特征：

- 背景约为 `RGB(245,245,245)`。
- 白色区域约占整张截图的 `8.45%`。
- 区域内约 `94.6%` 的像素属于高亮像素。
- 区域大、连续、颜色均匀、接近矩形。
- 周围页面为深色，内外亮度差明显。

该案例会被以下规则共同命中：

```text
大面积亮色区域
+ 高亮像素占比
+ 低纹理均匀背景
+ 与外围明显反差
+ 规则矩形形状
```

在输入确为预期暗夜页面且该亮区不是允许素材的前提下，可独立产生严重背景未适配候选。

若文字为 `RGB(181,181,181)`、卡片为 `RGB(245,245,245)`，真实 WCAG 对比度约为 `1.88:1`。白底灰字也可能是白天模式的正常配色或禁用态；纯截图不能推断其业务意图。

本版默认 `theme_mismatch` 下，该组合不满足“暗笔画＋深背景”门控，因此不产生专项文字告警，白卡背景异常仍保留。开启 `all_low_contrast` 后，应按实测约 1.88:1 提示并复核；算法不能把它改算为高对比度。

### 15.2 案例二：黑色文字配深色背景

截图中的异常区域具有以下特征：

- 卡片背景约为 `RGB(37,37,40)`。
- 异常文字核心像素约为 `RGB(23,23,23)`。
- 文字与背景只有约 14 个灰度级差异。
- 对比度约为 `1.17:1`。
- 背景颜色均匀。
- 弱笔画呈现明显的文本行排列。

该案例不会触发亮色背景检测，必须由独立文本链路发现：

```text
Black-hat 暗笔画响应
+ Sobel 弱边缘
+ 水平文本行结构
+ 相反梯度边缘配对及稳定核心／双侧背景
+ 暗笔画与局部深色背景门控
+ 足够数量及比例的低对比度配对
+ 对比度低于 2:1
```

在文字结构和配对质量成立时，该区域产生严重低对比度文字候选。

这两个案例说明背景检测与文本检测必须并行，而不能设计为前后依赖关系。

## 17. 流水线判定策略

> 算法：严重程度、启发式置信度、requiresReview 与模块状态的规则状态机，无对应论文。

建议不要让所有算法告警直接导致构建失败。

| 条件 | 建议处理 |
| --- | --- |
| 严重且高置信度 | 测试失败 |
| 高风险且高置信度 | 测试失败或强制人工审核 |
| 严重但低置信度 | 人工审核 |
| 中风险 | 生成提示，不阻塞构建 |
| 无法可靠判断 | 进入人工审核，不计为通过 |
| 命中白名单 | 记录但不告警 |

第一版上线时可以只生成报告，不阻塞 CI。待阈值稳定后，再逐步启用高置信度严重问题的阻塞策略。

## 18. 性能与资源

### 18.1 硬件要求

方案不需要：

- GPU。
- 独立显卡。
- 神经网络推理设备。
- 大内存服务器。

普通开发电脑、Mac mini 或 CI CPU Worker 即可运行。

### 18.2 原图内存估算

以 `1080×2400` 截图为例：

```text
RGB 图：约 7.8 MB
灰度图：约 2.6 MB
单张 8 位掩码：约 2.6 MB
```

以上只算最基础的 8 位图，不能据此承诺单任务仅几十 MB。浮点亮度、梯度、32 位连通域标签、形态学响应、射线矩阵、NumPy 临时数组以及截图／链路并发都会增加峰值。

0.1.0 本机两截图并发验证曾记录进程峰值 RSS 约 664 MiB；该值是特定合成输入和配置的历史记录，不是 0.4.0 的资源保证。资源预算以目标 CI 主机实测为准，内存受限时先设置 `--workers 1`。

### 18.3 性能策略

- 直接使用原始分辨率，不进行缩放。
- 全图运行传统图像操作。
- 控制批处理并发数。
- 一张截图处理完成后及时释放中间矩阵。
- 调试模式才保存中间掩码。
- 正常模式只保存异常标注图和结构化结果。
- 多尺度文本检测只保留少量必要尺度；每组件限制射线数，配对计算在组件内向量化。
- 先执行灰度、亮度和基础掩码等低成本计算，再对候选区域执行纹理、颜色和对比度分析。
- 两条检测链路共享灰度图、亮度图和基础梯度结果，避免重复计算。
- 可评估积分图或区域前缀统计加速矩形查询；当前实现未将其作为核心优化，不列为已完成。
- 窄边候选使用轻量的边缘长度和连续性统计，不对整张图重复执行复杂形态学运算。

单张耗时应通过目标运行环境实测。传统形态学、边缘和连通区域算法通常可以在普通 CPU 上完成，不需要单独采购硬件。

## 23. 能力边界

### 23.1 完全同色文字

如果文字和背景颜色完全相同，最终截图中不存在任何文字轮廓。纯截图算法无法知道该位置原本存在文字。

如必须覆盖，需要额外引入：

- Android View 层级。
- Accessibility 节点。
- Compose Semantics。
- 自动化用例提供的预期控件区域。
- 白天模式截图中的稳定区域信息。

这些能力不属于当前纯截图方案。

### 23.2 复杂图片背景

复杂图片、渐变和视频背景上的低对比度文字可能产生误报或漏报。此类问题应降低自动判断置信度，并进入人工确认。

### 23.3 设计意图

算法无法完全理解某个亮色区域是不是设计允许的效果，因此白名单、风险分级和人工复核仍然必要。

### 23.4 候选与测量覆盖边界

本方案提供的是疑似文字组件与若干笔画截面测量，不保证找到全部文字，不保证每个组件等于一个字，也不能从采样成功推断一定是文字。专项模式故意排除部分低对比度组合；全量模式也受候选提取与采样成功率约束。

配对失败、孤立未测组件、极细字体和未知复杂背景都可能漏检。“未告警”只表示启用规则没有发现问题，不能当作全页所有文字已被测量。后续若要提高候选召回、解决粘连或引入跨尺度投票，应单独设计、标注和验收。

### 23.5 阈值通用性

不同应用的暗色主题和品牌色不同。文档中的阈值是初始参考值，必须使用真实截图集校准。

## 24. 本版技术组合与实施边界

最终采用：原始 PNG、两套明确区分的亮度定义、底色／纹理／边界／布局图片候选与原图 ROI SLICO、背景专用可信内部掩码、剩余 UI 统计、独立背景／文本链路、背景多分支阈值与原掩码窄边、数学形态学、Sobel、8 邻域 CCL、水平候选组合、借鉴 SWT 的局部相反梯度配对、核心与双侧背景取样、极性局部门控、逐配对 WCAG 对比度和组件支持判定。

本方案不使用缩略图、OCR、神经网络或 GPU，不宣称完整 SWT、字形识别、图片语义分类或完整 WCAG 合规审计。论文支撑基础算子或借鉴思想；门控、双侧取样、支持阈值和风险策略是本项目工程设计，必须用真实样本验证。
